# Contributing

Thanks for helping. Bug reports with an OBS log are the most useful thing you can send:
**Help > Log Files > Upload Current Log File** in OBS, then paste the link in the issue.

## Build

```bash
./scripts/fetch-deps.sh                      # libobs 30.0 headers and SIMDe
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

- **Windows and Linux** need ONNX Runtime: `python3 scripts/fetch-onnxruntime.py <win-x64|win-arm64|linux-x64|linux-arm64>`
  prints the library's path; pass it as `-DORT_LIB=...`. On Windows, run
  `scripts/make-import-libs.ps1` in a Visual Studio developer shell first.
- **macOS** uses Apple's Vision framework. To try the ONNX backend instead (as Windows and Linux
  do): `-DPOLISH_BACKEND=onnx -DCMAKE_OSX_ARCHITECTURES=arm64 -DORT_LIB=$(python3 scripts/fetch-onnxruntime.py osx-arm64)`.

## Test

```bash
cmake -S . -B build -DPOLISH_TESTS=ON && cmake --build build
python3 tests/run_tests.py                   # renders go to tests/out/
```

The tests start a real libobs with no window and check the pixels; see the comments in
`tests/render_test.c` for pointing them at an OBS installation. CI runs them on macOS, Windows
(x64, ARM64) and Linux (x86_64 with the newest OBS, ARM64 with OBS 30).

## Guidelines

- Plain C for the plugin (Objective-C only in `backend-vision.m`), libobs's style: tabs, 120 columns.
- Every effect has a test that would fail if it stopped working; add one with a new effect.
- Assets are generated by `tools/make_assets.py`. Please don't add third-party art.
- Build against the oldest supported libobs (30.0) and use only APIs it has.
